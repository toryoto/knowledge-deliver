# Obsidian Agent — システム設計仕様書

## 1. 概要

### プロダクト概要
個人の Obsidian Vault（git 管理）に Claude Agent SDK でアクセスし、Slack などのクライアントから自然言語でノートの読み書き・検索・要約を行えるシングルテナントの AI エージェントシステム。

### 設計方針
- **シングルテナント前提**: 自分1人が使う前提で設計する
- **関心の分離**: Vault はデータ、Agent はアプリケーションとして完全に分離する
- **クライアント非依存**: Agent Endpoint を中心に設計し、Slack などは薄いクライアントとして扱う
- **ソース非依存**: リクエストの発生元（Slack・外部API・cron）を Agent 側で意識しない設計にする
- **OSS 配布可能**: 環境変数の設定だけで誰でも自己ホストできる

## 2. システムアーキテクチャ

### 全体構成

```
GitHub
├── obsidian-vault/        (ノートデータ + CLAUDE.md + Skills)
└── obsidian-agent/        (アプリケーションコード)
    ├── agent-server/      (Agent Endpoint)
    ├── slack-bot/         (Slack クライアント)
    └── pipeline/          (外部データソース連携・定期実行)

Railway
├── agent-server           (コンテナ + Persistent Volume)
├── slack-bot              (コンテナ)
├── pipeline               (コンテナ・cron)
└── Redis                  (セッション管理)
```

### リクエストフロー

```
Slack / 外部データソース / cron
  │  各クライアント固有の処理
  ▼
slack-bot / pipeline (Railway)
  │  POST /agent { message, source, sessionKey }
  ▼
agent-server (Railway)
  │  Claude Agent SDK
  │  cwd: /vault/obsidian-vault (Persistent Volume)
  │  CLAUDE.md: Vault 構造・記法ルール（settingSources で自動読み込み）
  │  Skills: .claude/skills/ （settingSources で自動発見）
  ├── Grep / Glob / LS で自律探索 (Agentic RAG)
  ├── Read / Write でノート操作
  └── Stop Hook → git push → obsidian-vault
```

### Vault 同期フロー

```
起動時
  └── /vault/obsidian-vault が存在しなければ git clone

Obsidian (ローカル) でノート編集
  └── git push
        └── GitHub Webhook → POST /webhook/github
              └── git pull (非同期・競合なし)

Agent によるノート書き込み
  └── Stop Hook → git add / commit / push
        └── GitHub Webhook → git pull (自己反映)
```

> **設計上の理由**: CLAUDE.md・SKILL.md はいずれも「Vault が何者であるか・どう操作するか」を記述したVault 固有の知識であり、Vault と共に管理されるべき。
> Agent はそれを読むだけで、Vault の知識を Agent リポジトリに持たない。
> これにより `cwd` を変えるだけで別 Vault にも同じ Agent が使え、Cursor・Claude Code CLI など他のツールも同じ `.claude/` を参照できる。

## 4. コンポーネント仕様

### 4-1. agent-server

#### エンドポイント一覧

| Method | Path | 説明 |
|--------|------|------|
| POST | /agent | Agent へのメッセージ送信（SSE ストリーミング） |
| POST | /webhook/github | GitHub push Webhook 受信・git pull トリガー |
| GET | /health | ヘルスチェック |

#### POST /agent

**リクエスト**
```json
{
  "message": "今日のデイリーノートをまとめて",
  "source": "slack",
  "sessionKey": "1234567890.123456"
}
```

- `source`: リクエストの発生元。`slack` / `pipeline` / `webhook` など
- `sessionKey`: セッション継続のキー。Slack なら `threadTs`、pipeline なら job 名など発生元が自由に設定する

**レスポンス**（JSON・同期）
```json
{
  "text": "本日のノートの要約:..."
}
```

> SSE ストリーミングは後回し。Agent の処理完了後にまとめて返す同期レスポンスで実装する。

**セッション管理**
- `source:sessionKey` をキーに Redis から `sessionId` を取得
- 存在すれば `resume: sessionId` で会話継続
- 存在しなければ新規セッション → 生成された `sessionId` を Redis に保存
- Redis TTL: 7日間

#### POST /webhook/github

**処理フロー**
1. `x-hub-signature-256` ヘッダーで署名検証
2. 検証成功 → `200 OK` を即返す
3. バックグラウンドで `git pull` を非同期実行
4. `isSyncing` フラグで同時実行を防止

#### 環境変数

| 変数名 | 説明 | 必須 |
|--------|------|------|
| ANTHROPIC_API_KEY | Anthropic API キー | ✅ |
| VAULT_REPO_URL | Vault の git clone URL | ✅ |
| VAULT_PATH | Persistent Volume のマウントパス（例: /vault/obsidian-vault） | ✅ |
| GITHUB_TOKEN | git push 用 Personal Access Token | ✅ |
| GITHUB_WEBHOOK_SECRET | Webhook 署名検証用シークレット | ✅ |
| REDIS_URL | Redis 接続 URL | ✅ |
| PORT | サーバーポート（デフォルト: 3000） | ✅ |

### 4-2. slack-bot

#### Slack App 設定

| 設定項目 | 値 |
|----------|----|
| Socket Mode | ON |
| Event Subscriptions | `app_mention`, `message.im` |
| Slash Commands | `/note`, `/daily`, `/search` |

#### イベントハンドラ

**app_mention**
- メンション本文を `message` として `/agent` を POST
- スレッドの `ts` を `threadTs` として送信（会話継続のため）
- 結果をスレッド返信で投稿

**message.im（DM）**
- メッセージ本文をそのまま `message` として `/agent` に POST
- DM の `ts` を `threadTs` として送信

**slash コマンド `/note <内容>`**
- `今日のデイリーノートに以下を追記してください: <内容>` として `/agent` に POST
- 確認メッセージを返信

#### 環境変数

| 変数名 | 説明 | 必須 |
|--------|------|------|
| SLACK_BOT_TOKEN | xoxb-... | ✅ |
| SLACK_APP_TOKEN | xapp-... (Socket Mode) | ✅ |
| AGENT_ENDPOINT_URL | agent-server の URL | ✅ |

### 4-3. CLAUDE.md と Skills の役割分担

| ファイル | 配置場所 | 役割 | 読み込み方法 |
|----------|----------|------|-------------|
| `CLAUDE.md` | obsidian-vault/ | Vault の構造・記法ルール・ディレクトリ説明。Agentic RAG の道標 | `settingSources: ["project"]` で自動読み込み |
| `SKILL.md` | obsidian-vault/.claude/skills/ | 操作手順・ロジック（デイリーノートの書き方・検索手順など） | `settingSources: ["project"]` で自動発見 |

```typescript
// agent.ts での設定
query({
  options: {
    cwd: VAULT_PATH,                   // CLAUDE.md・Skills はここから読み込まれる
    settingSources: ["project"],        // cwd/.claude/ と CLAUDE.md を読み込む
    allowedTools: ["Skill", "Read", "Write", "Grep", "Glob", "LS"],
  },
})
```

### 4-4. Skills

#### daily-note/SKILL.md

```markdown
---
name: daily-note
description: >
  Obsidian のデイリーノートを読む・書く・更新する。
  「今日」「昨日」「デイリー」などのキーワードが含まれる場合に使用する。
---

# デイリーノート操作

## ファイルパス規則
- 場所: Daily/YYYY-MM-DD.md
- 今日: Daily/{today}.md
- 昨日: Daily/{yesterday}.md

## フォーマット
\`\`\`markdown
# YYYY-MM-DD

## タスク
- [ ] タスク名

## メモ
内容

## 完了
- [x] 完了したタスク
\`\`\`

## 操作ルール
- ファイルが存在しない場合は上記フォーマットで新規作成する
- 追記の場合は既存の内容を保持した上で末尾に追加する
- [[wikilink]] 形式の内部リンクをそのまま保持する
- #タグ 形式のタグをそのまま保持する
```

#### search-notes/SKILL.md

```markdown
---
name: search-notes
description: >
  Vault 内のノートをキーワード・タグ・リンクで横断検索する。
  「探して」「検索」「関連する」などのキーワードが含まれる場合に使用する。
---

# ノート検索

## 検索手順
1. Glob でファイル一覧を取得する
2. Grep でキーワードを含むファイルを絞り込む
3. 関連度の高いファイルを Read して内容を確認する
4. [[wikilink]] のリンクを辿って関連ノートも参照する

## 検索パターン
- キーワード検索: Grep で本文検索
- タグ検索: Grep で `#タグ名` を検索
- リンク検索: Grep で `[[ノート名]]` を検索
- 日付範囲: Glob で `Daily/2026-04-*.md` のようにパターン指定
```

#### import-content/SKILL.md

```markdown
---
name: import-content
description: >
  外部から取得したコンテンツ（URL・テキスト・構造化データ）を
  Obsidian のノートとして取り込む。
  「保存して」「インポート」「追加して」などのキーワードが含まれる場合に使用する。
---

# 外部コンテンツ取り込み

## 保存先の決定ルール
- URL・記事: Resources/YYYY-MM-DD-{タイトル}.md
- 短いメモ・引用: 今日のデイリーノートに追記
- 構造化データ（リスト形式）: 内容に応じて Projects/ または Areas/ に保存

## フォーマット
\`\`\`markdown
# {タイトル}

source: {元URL or 取得元}
date: {取得日}
tags: #{カテゴリタグ}

---

{本文・要約}
\`\`\`

## 操作ルール
- 既存ノートとの関連がある場合は [[wikilink]] でリンクを張る
- タグは既存のタグ体系に合わせる（Grep で既存タグを確認してから付与）
- 重複コンテンツは作成しない（Grep でタイトル・URL を事前確認）
```

### 4-5. Hooks

#### PreToolUse: Vault 外書き込みブロック

```typescript
{
  matcher: "Write",
  callback: async (input: PreToolUseHookInput) => {
    const filePath = input.tool_input?.file_path as string;
    if (!filePath.startsWith(VAULT_PATH)) {
      return { decision: "block", reason: "Vault 外への書き込みは禁止" };
    }
    return { decision: "allow" };
  },
}
```

#### Stop: git push

```typescript
{
  callback: async () => {
    await commitAndPush("auto: agent update");
    return {};
  },
}
```

## 5. データ設計

### Redis キー設計

```
session:{source}:{sessionKey}  → {sessionId}  TTL: 7日

# 例
session:slack:1234567890.123456       → {sessionId}
session:pipeline:import-liked-posts   → {sessionId}
```

### CLAUDE.md（obsidian-vault/ ルートに配置）

`settingSources: ["project"]` により `cwd`（= Vault）配下から自動的に読み込まれる。
Agentic RAG 時にエージェントが Vault 内を探索する際の道標となる。

```markdown
# Obsidian Vault

このリポジトリは個人の Obsidian Vault です。

## ディレクトリ構造
- Daily/        : デイリーノート（YYYY-MM-DD.md）
- Projects/     : プロジェクトノート
- Areas/        : 継続的な関心領域
- Resources/    : 外部コンテンツ・参考資料

## 記法ルール
- 内部リンク: [[ノート名]]
- タグ: #タグ名
- タスク: - [ ] 未完了 / - [x] 完了

## 操作上の注意
- .obsidian/ ディレクトリは読み取り専用（設定ファイル）
- ファイルの削除は行わない
- 既存ノートを編集する場合は既存内容を必ず保持する
```

## 6. インフラ構成（Railway）

### サービス構成

| サービス名 | ソース | Persistent Volume | 備考 |
|------------|--------|-------------------|------|
| agent-server | obsidian-agent/agent-server | /vault（10GB） | Webhook 受信 |
| slack-bot | obsidian-agent/slack-bot | なし | Socket Mode |
| pipeline | obsidian-agent/pipeline | なし | cron・外部データソース連携 |
| Redis | Railway テンプレート | なし | セッション管理 |

### Persistent Volume

```
マウントパス: /vault
サイズ: 10GB（Hobby プラン）
用途: Obsidian Vault の git clone 先（CLAUDE.md・Skills を含む）
注意: 1サービス1ボリュームのみ・スケールアウト不可
```

### デプロイフロー

```
obsidian-agent リポジトリに push
  └── Railway が自動ビルド・デプロイ
        └── コンテナ起動時に initVault() 実行
              ├── /vault/obsidian-vault が存在しなければ git clone
              └── 存在すれば何もしない（Webhook で最新化済み）
```
